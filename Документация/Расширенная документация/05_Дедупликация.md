# Дедупликация

`InMemoryDedupStore` защищает от повторной обработки одинаковых событий. Реализация использует двойную структуру данных для баланса между производительностью и контролем памяти.

---

## Структура данных

Два компонента работают совместно:

| Компонент | Тип | Назначение |
|-----------|-----|------------|
| `_items` | `set[str]` | O(1) проверка наличия ключа |
| `_order` | `deque[str]` | FIFO-порядок для удаления самых старых |

**Строки кода:** `storage.py:13-14`

---

## Операция `seen()`

Проверяет, присутствует ли ключ в `_items`. Если да — событие уже обрабатывалось.

Приобретает Lock для гарантии consistency между чтением `set` и `deque`.

**Строки кода:** `storage.py:16-18`

---

## Операция `add()`

### Алгоритм

1. Приобретает Lock
2. Проверяет, нет ли уже ключа в `_items` (защита от дублирования в deque)
3. Добавляет ключ в `_items` и `_order`
4. Если `_order` превышает `max_items`, извлекает самый старый элемент из deque и удаляет из set

### Эвикция

При превышении лимита (по умолчанию 10,000 элементов) каждый новый `add()` удаляет ровно один самый старый элемент. Это поддерживает скользящее окно из 10,000 последних событий.

```python
while len(self._order) > self.max_items:
    stale = self._order.popleft()
    self._items.discard(stale)
```

**Строки кода:** `storage.py:20-28`

---

## Ёмкость и её ограничения

- **По умолчанию:** 10,000 событий
- **Настраивается:** через параметр `max_items` в конструкторе
- **Эвикция:** FIFO (First In, First Out)

### Когда дедупликация перестаёт работать

Если событие было обработано более 10,000 событий назад, его ключ был удалён из хранилища. Повторное получение такого события приведёт к повторной обработке.

В контексте чат-бота это допустимо: дубликаты приходят в течение секунд, а не часов. Событие, пришедшее после 10,000 других — уже не дубликат.

---

## Потокобезопасность

Используется `threading.Lock` (не `RLock`). Это корректно, потому что:
- `seen()` не вызывает `add()` и наоборот
- Нет рекурсивных вызовов
- Lock защищает только мутации `_items` и `_order`

## Ключ дедупликации

Формируется вызывающим кодом (handler) и содержит:

**Для OpenLineMessage:**
```
event_type:connector_id:line_id:chat_id:message_id
```
**Строка:** `handlers.py:445-446`

**Для ConnectorMessage:**
```
event_type:connector_id:line_id:chat_id:im_message_id
```
**Строка:** `handlers.py:205-206`

**Для обычных сообщений (EchoMessageHandler):**
```
event_type:bot_id:dialog_id:message_id
```
Если `message_id` отсутствует, используется `message_text`.
**Строки:** `handlers.py:84-87`
