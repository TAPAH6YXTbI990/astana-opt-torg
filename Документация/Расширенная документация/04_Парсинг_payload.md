# Парсинг payload

Модуль `payloads.py` обрабатывает входящие webhook-запросы от Bitrix24, которые могут прийти в разных форматах: JSON, URL-encoded form data, или вложенные ключи в стиле PHP.

---

## Точка входа

Функция `load_payload()` вызывается в каждом webhook-обработчике:

```python
payload = load_payload(await request.body(), request.headers.get("content-type", ""))
```

**Строка кода:** `app.py:98`, `app.py:143`, `app.py:191`

---

## Двойной парсинг

### Приоритет 1: JSON

Если `Content-Type` содержит `json`, тело декодируется через `json.loads()`. Если результат — не словарь (например, список), он оборачивается в `{"value": data}`.

**Строки кода:** `payloads.py:49-54`

### Приоритет 2: URL-encoded form data

Если JSON-парсинг не удался или Content-Type указывает на form data, используется `parse_qs()` с `keep_blank_values=True`.

Для каждого ключа-значения:
- Одиночное значение используется напрямую
- Множественные значения становятся списком
- Ключи с квадратными скобками парсятся отдельно

**Строки кода:** `payloads.py:56-66`

### Fallback: сырой текст

Если оба парсинга завершились ошибкой, тело сохраняется в ключ `raw`.

**Строка кода:** `payloads.py:67-68`

## PHP-стиль вложенных ключей

Bitrix24 (написан на PHP) иногда отправляет form data с вложенными ключами:

```
data[PARAMS][DIALOG_ID]=123
data[PARAMS][MESSAGE]=Hello
user[name][first]=John
```

### `split_form_key()` — парсер квадратных скобок

Ручной парсер, который разбивает строку на компоненты:

| Вход | Результат |
|------|-----------|
| `data[PARAMS][DIALOG_ID]` | `["data", "PARAMS", "DIALOG_ID"]` |
| `user[name][first]` | `["user", "name", "first"]` |
| `simple_key` | `["simple_key"]` |
| `broken[key` | `["broken", "key"]` (обработка без закрывающей скобки) |

Алгоритм посимвольно обходит строку:
1. Накапливает символы в буфер
2. При `[` — сохраняет буфер, ищет закрывающую `]`
3. Содержимое между `[` и `]` добавляется как отдельный компонент
4. Незакрытые скобки обрабатываются корректно

**Строки кода:** `payloads.py:7-29`

### `assign_nested()` — динамическое построение дерева

Принимает список компонентов ключа и значение, строит вложенный словарь:

```
["data", "PARAMS", "DIALOG_ID"], "123"
→ {"data": {"PARAMS": {"DIALOG_ID": "123"}}}
```

На каждом промежуточном уровне проверяет, существует ли уже dict. Если нет — создаёт новый.

**Строки кода:** `payloads.py:32-40`

## Пример полного цикла

Входящий запрос:

```
Content-Type: application/x-www-form-urlencoded
Body: data[PARAMS][DIALOG_ID]=123&data[PARAMS][MESSAGE]=Hello
```

Результат:

```json
{
  "data": {
    "PARAMS": {
      "DIALOG_ID": "123",
      "MESSAGE": "Hello"
    }
  }
}
```

Этот результат затем передаётся в `events.py` для дальнейшего парсинга через mechanism lookup и resolve.
