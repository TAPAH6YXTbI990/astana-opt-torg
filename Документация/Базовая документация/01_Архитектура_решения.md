# Архитектура решения

## Общее описание

Проект представляет собой вебхук-бот для интеграции с Bitrix24. Бот принимает входящие события от Bitrix24 (сообщения в чатах, события открытых линий, установку приложения), обрабатывает их и отправляет ответы обратно через REST API Bitrix24.

## Описание ключевых компонентов

### 1. Точка входа (main.py / app.py)
- `main.py` — экспортирует экземпляр FastAPI приложения для запуска через uvicorn
- `app.py` — фабрика `create_app()`, создаёт и настраивает приложение, регистрирует маршруты

### 2. Конфигурация (config.py)
- Загружает настройки из `.env` через `python-dotenv`
- Централизованное управление всеми параметрами окружения
- Dataclass `Settings` с валидацией типов

### 3. Обработка событий (handlers.py)
Четыре основных обработчика:
- **EchoMessageHandler** — эхо-бот для обычных чатов (ONIMBOTV2MESSAGEADD)
- **OpenLineMessageHandler** — обработка сообщений открытых линий (ONOPENLINEMESSAGEADD) с вызовом внешнего сервиса
- **OpenLinesConnectorHandler** — альтернативный обработчик для коннекторов
- **AppInstallHandler** — обработка установки приложения (ONAPPINSTALL), сохранение токенов, авто-привязка событий

### 4. Модели событий (events.py)
- `IncomingEvent` — события от ботов в чатах
- `OpenLineEvent` — события открытых линий
- `ConnectorEvent` — события коннекторов
- `AppInstallEvent` — событие установки приложения
- Вспомогательные функции для извлечения данных из разнородных payload

### 5. Клиенты Bitrix24
- **BitrixClient** — использует `fast-bitrix24` для вызовов через webhook (бот)
- **OAuthBitrixClient** — прямые HTTP-запросы к REST API от имени приложения с авто-обновлением токенов

### 6. Аутентификация приложения (app_auth.py)
- `AppAuth` — dataclass с токенами (access, refresh, application_token)
- `AppAuthStore` — потокобезопасное сохранение/загрузка в JSON файл

### 7. Утилиты
- **payloads.py** — парсинг JSON и form-data, поддержка вложенных ключей
- **storage.py** — InMemoryDedupStore для защиты от дублей в рамках процесса
- **register_bot.py** — CLI для регистрации бота в Bitrix24
- **bind_openlines.py** — CLI для ручной привязки события ONOPENLINEMESSAGEADD

## Поток данных

1. **Входящий webhook** → FastAPI route → `load_payload()` → парсинг в модель события
2. **Модель события** → соответствующий Handler → бизнес-логика
3. **Исходящий запрос** → BitrixClient или OAuthBitrixClient → REST API Bitrix24
4. **Дедупликация** → InMemoryDedupStore проверяет/добавляет ключи
5. **Логирование** → структурированные логи с санитизацией секретов

## Принципы архитектуры

- **Разделение ответственности**: каждый модуль отвечает за свою область
- **Dependency Injection**: настройки и клиенты передаются в обработчики
- **Stateless handlers**: бизнес-логика не хранит состояние, использует внешние хранилища
- **Безопасность**: санитизация логов, проверка секретов в webhook URL
- **Расширяемость**: легко добавить новые типы событий и обработчики
