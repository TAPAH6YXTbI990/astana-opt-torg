# Промпты и описание

## Общее назначение

В текущей версии проекта **промпты в классическом понимании (инструкции для LLM) отсутствуют**. Бот работает в режиме **эхо-бота** — он просто возвращает пользователю тот же текст, который получил.

Однако архитектура предусматривает точку интеграции с внешним сервисом генерации ответов, который может использовать промпты.

## Точка интеграции с внешним ИИ

### OpenLineMessageHandler (handlers.py)

В методе `handle()` для каждого входящего сообщения открытой линии происходит вызов внешнего вебхука:

```python
external_answer = self._request_external_answer(
    message_text=reply_text,
    session_id=str(message.message_user_id),
)
```

### Формат запроса к внешнему сервису

**Метод:** POST  
**Content-Type:** application/json  
**URL:** задаётся переменной окружения `BITRIX_OPENLINE_RESPONSE_WEBHOOK_URL`

**Тело запроса:**
```json
{
  "message": "Текст сообщения пользователя",
  "session_id": "ID пользователя в Bitrix24"
}
```

### Ожидаемый формат ответа

**Content-Type:** application/json

```json
{
  "output": "Текст ответа для пользователя"
}
```

### Поле `session_id`

Используется для поддержки контекста диалога. В текущей реализации передаётся `message_user_id` — уникальный идентификатор пользователя в Bitrix24. Это позволяет внешнему сервису:
- Поддерживать историю диалога для конкретного пользователя
- Персонализировать ответы
- Реализовывать многошаговые сценарии

## Переменные окружения, связанные с внешним сервисом

| Переменная | Описание |
|------------|----------|
| `BITRIX_OPENLINE_RESPONSE_WEBHOOK_URL` | URL внешнего сервиса генерации ответов (по умолчанию: https://builder.smartybotapps.ru/webhook/amoBitrixTest) |

## Миграция на полноценного ИИ-бота

Для перехода от эхо-бота к ИИ-боту необходимо:
1. Развернуть сервис, принимающий POST запросы в описанном формате
2. Реализовать логику промптинга и вызова LLM
3. Вернуть JSON с полем `output`
4. Указать URL сервиса в `.env`

Текущая архитектура не требует изменений в коде бота для этого перехода.
